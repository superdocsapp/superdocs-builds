When this fires

The PaymentsApiErrorBudgetBurn alert fires when the fast-burn error ratio for payments-api stays above 0.02 for 5 minutes, measured over a 5-minute window.

The related PaymentsApiHighLatency alert fires when p99 request latency stays above 750ms for 10 minutes.

Dashboards: Payments overview and Latency detail.

Triage

Start with pod health. The deployment is payments-api in namespace payments, and it runs 4 replicas.

bash

If pods are healthy, check the database. The primary is meridian-payments-prod in region eu-west-1.

On a shared cluster you may need to name the namespace yourself:

bash top pods]]>

Mitigation

Restart the deployment first, since it clears a wedged connection pool without needing a release:

bash

If a bad release is the cause, re-run the rollback-production job in the deploy workflow. It needs a production environment approval, so find a second reviewer before you start.

Escalation

Page the Payments Platform rota if latency stays above the threshold for 30 minutes, or immediately if checkout is failing.

For anything touching card data, also notify the Fulfilment rota so despatch can pause.
