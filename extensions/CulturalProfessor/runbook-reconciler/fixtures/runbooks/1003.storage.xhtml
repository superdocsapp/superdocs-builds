When this fires

The TrackingIngestPodRestarts alert fires when pods in the tracking namespace restart more than 3 times in an hour.

Triage

The deployment is tracking-api in namespace tracking, running 4 replicas behind the carrier event queue.

Restarts are almost always the memory limit. Check current usage against the limit before anything else:

bash top pods kubectl -n tracking get events --sort-by=.lastTimestamp | tail -20]]>

If the pods are being OOM-killed, the limit is 1Gi and raising it is a platform change, not an incident action.

Escalation

Page the Tracking rota. There is no secondary; it goes to the head of platform after 20 minutes.
