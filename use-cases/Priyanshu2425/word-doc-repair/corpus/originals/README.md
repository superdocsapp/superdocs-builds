# The originals — where they came from, and why these

These are **undamaged** documents. Nothing in this directory is broken: the
corpus is generated by damaging these files at run time, so the repository
carries the sources and the truth rather than 87 broken binaries and a promise
about what used to be in them.

Two more base documents are written by this package at run time
(`corpus._report` and `corpus._illustrated`) and are not files.

## Why documents this package did not write

A repair tool measured only against its own output is measured against its own
assumptions. Each of these three lays out its XML in a way this package never
would — Google Docs nests its runs differently, `textutil` writes no styles part
at all, and the `variations` file splits words across runs wherever formatting
changes, which is what Word itself does and what this package's writer does not.

That last one is not a curiosity: it broke the measurement the first time it
ran, and then it found a real defect in the product. See `../../RECOVERY.md`.

## Why not a corpus of genuinely corrupt files

There does not appear to be one. What was looked at, and why each was not used,
is recorded in `../../RECOVERY.md` under *What was looked for and not found*.
The short version is that a recovery **rate** needs to know what the file said
before it broke, and a corrupt file found in the wild does not come with that.
