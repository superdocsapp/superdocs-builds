# Where SuperDocs sells — ten use cases with named buyers

**Built by Jyotiraditya Singh for the SuperDocs Round 2 engineering task.**

## What this is, in plain language

Market research, not a running application. Ten real-world use cases for
SuperDocs, each with the specific role that owns the budget, the pain that
justifies the spend, named companies that would plausibly buy, and the wedge
that gets you in the door.

It is filed here rather than only on the submission form because the analysis is
more useful to other builders than to a reviewer alone: several entries name a
concrete first product to build, and duplicates are explicitly welcome in this
repository.

**Read it:** [`use-cases.md`](use-cases.md)

## How to run it

Not applicable — there is no code here. It is a single Markdown document meant
to be read.

## What SuperDocs features it reasons about

No API calls were made; this is desk research. The analysis is built on the
product's documented capabilities — in-place targeted edits, review and
approval before changes commit, export, and the REST and MCP surfaces — and on
the boundaries stated publicly, particularly that SuperDocs edits documents
rather than acting as an archive or a spreadsheet editor. Each use case is
filtered on one test: the document already exists, it changes constantly, and a
wrong change is expensive.

## Honest limitations

- **I did not contact any company named here**, and the round's rules require
  that. This is reasoning about who would buy, not validated demand.
- **I know nobody personally at any company listed.** No warm introductions are
  implied.
- Company names are illustrative of a buyer profile. Treat them as a starting
  point for research, not as a qualified pipeline.
- I did not use the product before writing this, so the analysis rests on the
  documentation rather than on hands-on experience. That is a real weakness and
  I would weight it accordingly.
