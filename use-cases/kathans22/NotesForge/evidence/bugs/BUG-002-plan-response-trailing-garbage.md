# BUG-002: `planCompliancePacks` discards an otherwise-valid JSON response over two trailing characters

**Date:** 22 August 2026
**What I did:** `compliance --generate` (all 8 clients) — user-reported failure, reproduced independently by dumping the raw `response.response` bytes from `planCompliancePacks` across 5 live calls (`JSON.stringify`'d to a file so escaping is unambiguous, not read off the terminal).
**Expected:** The model's single planning `chat()` call returns `{"outlines": [...]}` and `JSON.parse` (after fence-stripping) succeeds every time.
**Got instead:** ~60% of calls (3 of 5 in the reproduction) returned a string that is a **complete, valid** `{"outlines": [...]}` object with two stray characters — `"` then `}` — appended immediately after the real closing brace. Confirmed byte-exact via the dump: first 40 chars always `{"outlines": [{"client_id": "CL-01", "ti`; last 80 chars always end `...]}]}]}"}` — i.e. `]}]}]}` (a fully balanced close: source_notes array → section object → sections array → outline object → outlines array → root object) followed by exactly `"}` and nothing else. This is not the classic "whole payload re-encoded as a JSON string" double-encoding shape (which would start with a literal `"` too) — it's a valid object with a small leaked fragment tacked on the end, most likely from the underlying model's own JSON-mode framing leaking through on longer completions.
**How badly it blocked:** Fully blocking, not cosmetic — `planCompliancePacks` threw `CompliancePlanParseError` and `compliance --generate` failed before any pack was drafted, on a majority of runs, discarding an otherwise-complete and usable response every time.
**Repro:**
1. Run `compliance --generate` (or any call through `planCompliancePacks`) against the full 8-client roster (a large single JSON response increases the odds of hitting this).
2. On failure, catch `CompliancePlanParseError` and inspect `.rawResponse` — `JSON.stringify(rawResponse.slice(-80))` shows the trailing `"}` after an otherwise balanced object.
3. Repeat 4-5 times; failure recurs intermittently (observed ~60% failure rate, not deterministic).
**Workaround adopted:** Added `parseJsonLoosely()` and `extractBalancedJson()` to `src/compliance/plan.ts`, used by both `planCompliancePacks` and `coverage.ts`'s suitability model-escalation. On a direct-parse failure, it scans from the first `{`, tracks brace depth (skipping over content inside string literals), and parses just the first balanced top-level object it finds — recovering the real payload instead of discarding it. The direct-parse path also still re-parses once if the result is a plain string, covering genuine double-encoding if that shape ever occurs elsewhere. Regression-tested in `src/compliance/plan.test.ts` (`npm test`, Node's built-in test runner — no new dependency) against this exact trailing-garbage shape, a genuine double-encoded payload, and real malformed input that should still throw. Retested `compliance --generate` against all 8 clients live after the fix.
