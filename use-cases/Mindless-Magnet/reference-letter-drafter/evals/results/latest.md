# Calibration eval

Generated by `npm run eval` at 2026-08-19T02:44:51.551Z. Do not edit by hand.

## Method, stated before the result

Each synthetic intake in `evals/fixtures/intakes.json` declares a strength band. The drafter produces a letter. A **second, isolated SuperDocs chat turn** (fresh session, no cross-session memory) then reads the letter alone, with no access to the declared band, the intake, or the drafting prompt, and infers what band a reader would take from it. Drift is the inferred rank minus the declared rank on a four-point scale (reluctant 1, mixed 2, solid 3, strong 4).

**Positive drift means the letter reads warmer than the writer meant.** That is the failure this tool exists to catch, so it is reported signed rather than as an absolute error.

- Drafting model: `SuperDocs default tier`
- Verifier model: `SuperDocs (second, blind chat pass)`
- SuperDocs operations spent: 16
- Raw per-run data: `evals/results/runs.jsonl` (committed)

## Limits of this measurement

- The sample is small by design. Each letter costs a SuperDocs operation, and the harness has a hard `--max-ops` stopping rule so a run cannot quietly drain a free-tier budget.
- The ground truth is the band a human typed into a fixture, not an expert consensus. A panel of real referees would disagree with each other at the boundaries, particularly solid/mixed.
- The verifier is a language model. It is blind to the declared band, which removes the obvious bias, but it is not a neutral instrument and its own tendencies are unmeasured here.
- Fixtures are synthetic and written by one person, so they share a voice. Real intakes are messier, shorter, and more contradictory than these.
- Latency figures include network time for two separate SuperDocs chat calls (draft, then verify) and are not a benchmark of either one alone.
